# typeforme ideas, 2026-10-04

Inputs: brief with an unconfirmed ICP, interview skipped, voice guide empty, swipe file empty. Four writers (pain-first, demo-first, belief flip, outcome-first) produced twelve ideas; a cold critic ranked the twelve hooks. Every call to action carries `[WHERE TO GET IT]` because the destination is not decided.

Top two: I1 and I3.

### I1: The prompt I didn't type
- Angle: Outcome-first, merged with the demo-first version of the same idea
- Pain it targets: Typing a detailed prompt is slow, so they send a short, lazy one and get a worse result.
- Hook, spoken: "...and keep the existing tests passing, don't touch the config loader." Stop beep. "I didn't type any of that."
- Hook, on-screen text: I didn't type this prompt. I said it.
- Hook, first visual: Text landing at the cursor: a terminal, the pill at the bottom centre with bars moving to the voice, then dots, then a full paragraph of prompt landing at the cursor.
- Then show: 1) On camera: "This is typeforme. Hold Right Ctrl, talk, let go." 2) The same flow from the start at real speed: start beep, pill bars, release, stop beep, dots, text lands. 3) On camera: one clip can run up to five minutes, so you can give the context you would normally skip. 4) Text landing at the cursor in a second, non-terminal window. 5) On camera, the catch: Windows only, English only, needs internet, the audio goes to Groq, and setup is a free Groq API key, `uv sync`, `start.bat`.
- Call to action: "If you type prompts all day on Windows, get it at [WHERE TO GET IT]."
- Swipe pattern: none
- Critic note: Ranked 1st of 12 (the outcome-first version of the same idea ranked 3rd). The critic's one worry was that with the sound off it could pass for a paste or snippet tool, so the pill's moving bars must be in the first frame, before the text lands.
- Status: unused

### I2: Hold Right Ctrl. Talk. Let go.
- Angle: Demo-first
- Pain it targets: They want dictation that is simpler than the paid tools: no window to switch to and nothing to click.
- Hook, spoken: "Rename this function and update every call site." Stop beep.
- Hook, on-screen text: Hold Right Ctrl. Talk. Let go.
- Hook, first visual: The pill, close up, bars moving to the voice, with the terminal cursor blinking above it; release, dots, the sentence lands at the cursor.
- Then show: 1) On camera: "That pill never takes focus. Your cursor stays where it was." 2) Paste last dictation: click into a different app, press Ctrl+Alt+V, the same text lands again. 3) Tray menu: Copy last dictation and Start with Windows. 4) Error pill, red, "no internet". On camera: "If something's wrong, it tells you in a few words." 5) On camera: it's called typeforme, free to run, Windows only, and setup is a free Groq API key, `uv sync`, `start.bat`.
- Call to action: "Try it on your next prompt. It's at [WHERE TO GET IT]."
- Swipe pattern: none
- Critic note: Ranked 2nd; the whole mechanic reads in two seconds with the sound off. Not marked as a top pick because it overlaps I1 and its short spoken line does not sell the paragraph-of-context benefit, which the critic also noted.
- Status: unused

### I3: Clawed code
- Angle: Pain-first, merged with the belief-flip and demo-first versions of the same idea
- Pain it targets: They tried dictation, it mangled the tool names they say all day, and fixing the text took longer than typing it.
- Hook, spoken: "Every time I dictate, it writes 'clawed code'. Then I fix it by hand, so what was the point."
- Hook, on-screen text: I said "Claude Code". It typed "clawed code".
- Hook, first visual: The misspelling itself, large on screen as a caption over the terminal (changed from the writer's "maker wincing" on the critic's advice).
- Then show: 1) config.toml: the replacements table, where "cloud code", "clawed code", "claud code" and "clod code" all become "Claude Code", and the vocabulary list above it. 2) Text landing at the cursor: hold Right Ctrl, say a sentence with "Claude Code" and a few ums, release, it lands spelled right with the ums gone. Caption the raw spoken words next to the result so it works muted. 3) On camera: "It's plain rules you can read and edit. No AI rewriting what you said." 4) Tray menu: Open config, to show where you add your own words.
- Call to action: "Free, Windows only. Get it at [WHERE TO GET IT]."
- Swipe pattern: none
- Critic note: Ranked 4th and a clear "yes, stop": "the exact thing that made me give up on dictation". The belief-flip version, which opened on the config file, ranked 5th because a config file as the first frame "reads as homework", so the file moved to second position. Check before shooting: the app has to actually produce the misspelling for the caption to be honest; the replacements table suggests it did.
- Status: unused

### I4: Dictated all day, paid nothing
- Angle: Belief flip (good dictation needs a subscription), merged with the outcome-first and pain-first versions
- Pain it targets: Speaking is faster than typing, but the good dictation tools cost a monthly fee.
- Hook, spoken: "End of the day. I've dictated every prompt since this morning, and this is all of the free limit I used."
- Hook, on-screen text: Dictated all day. Paid nothing.
- Hook, first visual: Tray menu, zoomed until the usage line fills the frame: "Today: N dictations, N min (N% of free daily limit)".
- Then show: 1) On camera: "It runs on Groq's free tier. 2,000 requests a day, 8 hours of audio a day." 2) Text landing at the cursor: hold Right Ctrl, speak a prompt, release, text appears in the terminal. 3) The pill: bars, then dots. 4) On camera, the catch: no installer yet, so it's a free Groq API key, `uv sync`, then `start.bat`; Windows only; the audio is sent to Groq.
- Call to action: "It's called typeforme and it's free to run. Get it at [WHERE TO GET IT]."
- Swipe pattern: none
- Critic note: The three "free" hooks ranked 6th, 8th and 10th; the critic said they hit a real objection but trigger ad-skepticism unless the proof is on screen, and that the usage line would "rise a lot" if zoomed to fill the frame. Kept over the talking-head "8 hours a day, free" version (ranked higher at 6th) because this one shows proof and that one made the critic look for the catch. The spoken line is only true if shot at the end of a real day of use, with the real number on screen.
- Status: unused

### I5: The lazy prompt
- Angle: Pain-first
- Pain it targets: They know the full prompt, cannot be bothered to type it, send one line, and get a worse result.
- Hook, spoken: "I know what I want to ask. I just can't be bothered to type all of it."
- Hook, on-screen text: You knew the full prompt. You typed one line.
- Hook, first visual: A terminal with a one-line prompt being typed and sent (changed from the writer's "maker sighing at the keyboard" on the critic's advice).
- Then show: 1) Text landing at the cursor: the same request, spoken in full; hold Right Ctrl, start beep, speak, release, the whole paragraph lands. 2) The pill: bars, then dots. 3) On camera: "It's called typeforme. Hold Right Ctrl, talk, let go. Free, Windows only, English only, needs internet." 4) Tray menu: the usage line.
- Call to action: "If you're on Windows and you type prompts all day, get it at [WHERE TO GET IT]."
- Swipe pattern: none
- Critic note: Ranked 7th. The text landed ("describes exactly what I do") but the critic read it as a prompting-tips video and would not have guessed dictation. Kept as the only idea that opens on the viewer's own behaviour; the pill should appear by the third second so the fix is visible early.
- Status: unused

## Dropped

- "I want dictation, I don't want another subscription" (pain-first): a talking head with no proof; folded into I4.
- "It comes out clean" and "I said um twice" (outcome-first, demo-first): depend on hearing the ums, so they fail muted; folded into I3 as a supporting beat.
- "8 hours a day, free" (belief flip): folded into I4.
