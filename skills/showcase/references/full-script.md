# Full script mode

The user normally writes the script themself. Run this only when they ask for a full script, for the idea they name. If they do not name one, ask which.

Check the `platform` of the ideas run the idea is in. If it is `x`, follow "Writing a post in full" in `x.md` instead of the steps below, which are for a reel.

## Steps

1. Read the app's brief, the idea, the voice guide, and any swipe entry the idea cites.
2. Write the script as a beat table. Aim for 30 to 60 seconds, which is roughly 75 to 150 spoken words.

   | Time | Spoken | Picture | On-screen text |
   | --- | --- | --- | --- |
   | 0–3s | <the hook> | <on camera, or which screen> | <text> |

   - The first row is the idea's hook, unchanged unless the user asked for a change.
   - "Picture" is either the user on camera or a named screen or flow from the brief, with what to do on it ("add a client, the total updates").
   - End on the call to action from the brief.
3. Add a caption for the post under the table.
4. Write the spoken lines the way the voice guide says the user talks. Where the guide is thin, write plainly and short, as someone would say it aloud. If a `humanizer` skill is available, run the spoken lines through it.
5. Check it against the brief: every screen exists and every claim is true.
6. Save it as a draft and set the idea's status to `chosen`. Show the script in the reply.

The draft is a starting point for the user to rewrite. When they have shot the final version, `/showcase shot` records it, and the differences between this draft and what they shot are the best voice data the library gets.
